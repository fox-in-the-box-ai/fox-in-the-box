# v0.7.19 — Substrate cleanup

> **Heads up — clean install recommended.** Until Fox's upgrade path is fully validated end-to-end with automated smoke, the cleanest experience is to use **Tray → Reset Fox completely…** (v0.7.18+) or follow [`docs/RESET.md`](https://github.com/fox-in-the-box-ai/fox-in-the-box/blob/main/docs/RESET.md) before installing this release. This advisory will be removed once the upgrade path is verified across the matrix.

A release with no new features. Three connected substrate fixes and one gate hardening, all motivated by the six-hat audit that ran during the v0.7.17→v0.7.18 cycle. The point of this release is to restore trust in the substrate before the next user-facing work in v0.7.20.

## Highlights

- **The `@` prefix is gone from Fox's data directory.** Electron used to store user data at `~/AppData/Roaming/@fox-in-the-box` (Windows), `~/Library/Application Support/@fox-in-the-box` (macOS), and `~/.config/@fox-in-the-box` (Linux) — because Fox's npm scope (`@fox-in-the-box/electron`) was leaking into Electron's default app-name resolution. That `@` prefix was the systemic root of yesterday's cleanup mess where every standard command quietly missed the dir. v0.7.19 sets `productName: fox-in-the-box` explicitly and ships a one-time migration shim: if your old `@fox-in-the-box` dir exists and the new `fox-in-the-box` dir doesn't, Fox renames it on first launch. Zero data loss.
- **Documentation parity sweep — 8 files, −441/+147 lines.** Deleted `docs/GATEWAY.md` (410 lines describing a Stripe-billed LLM proxy that was parked alongside #90 / #91 weeks ago and that the README linked to as "Hermes Agent gateway internals" — completely wrong subject). Deleted empty `CODE_OF_CONDUCT.md` (broken link from README and CONTRIBUTING). Refreshed `docs/DEV_MODE.md` and `qa/SMOKE_CHECKLIST.md` headers that still said `v0.7.6`. Fixed `packages/fox-overlay/README.md` and `docs/architecture/upstream-overlay.md` patch counts (claimed "2 webui patches", actually 3 since v0.7.13) and added `test_hooks` to the webui_modules list.
- **SMOKE_LOG gate has teeth now.** v0.7.15 added a `release.yml` check that refused to publish a release unless `qa/SMOKE_LOG.md` had a matching `## vX.Y.Z` header. The body never had to contain anything — so v0.7.16 / v0.7.17 / v0.7.18 all shipped with headers in place but every checkbox left as `[ ]` placeholder. v0.7.19 adds a body-content check: the entry must contain at least one `- [x]` (real smoke was performed) OR an explicit `Bypass reason:` line (in-writing waiver). The gate that was being routed around for three consecutive releases is now real.
- **Branch protection updated.** `main` now requires the Playwright `smoke` and `validate-overlay` jobs in addition to the container build/smoke — the "intended REQUIRED" deferral that's been sitting since v0.7.15 is closed.

## Behind the scenes

- The six-hat audit (three architects + three engineers) ran during this cycle uncovered eight issues that had been silently fixed but never closed — `#340`, `#341`, `#330`, `#325`, `#343`, `#280`, `#290`, `#319`. All were closed with links to the commits that fixed them. The actionable backlog dropped from 27 to about 20 open.
- v0.7.19's own `SMOKE_LOG.md` entry is the first one written against the new gate teeth — engineering-side items (jest, node --check, doc-render verification) marked `[x]` pre-tag; user-facing migration smoke (upgrade from v0.7.18 on Windows with existing `@fox-in-the-box` data) deferred to post-release update.
