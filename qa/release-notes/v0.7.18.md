# v0.7.18 — Upgrades just work, Reset Fox tray menu, Ollama tile always visible

> **Heads up — clean install recommended.** Until Fox's upgrade path is fully validated end-to-end with automated smoke, the cleanest experience is to use **Tray → Reset Fox completely…** (this release adds it) or follow [`docs/RESET.md`](https://github.com/fox-in-the-box-ai/fox-in-the-box/blob/main/docs/RESET.md) before installing this release. This advisory will be removed once the upgrade path is verified across the matrix.

Almost everything in this release traces back to one debugging session right after v0.7.17 shipped. Three problems surfaced at once: the upgrade had no visible effect because Fox kept running the old container against the old image, getting back to a clean slate required manual `cmd /c rd /s /q` voodoo because there was no in-app reset, and the Ollama provider tile was hidden entirely when Ollama wasn't installed — so users couldn't even discover Fox supported local models. All three are closed here.

## Highlights

- **Upgrades actually upgrade.** When `:stable` advances, Fox now detects that the running container was built from an older image digest and recreates it on next launch. `/data` and the workspace mount survive the recreate — conversations, memory, settings, profiles all preserved. Closes #340.
- **"Reset Fox completely…" in the tray menu.** One click stops the container, removes the image, and deletes all Fox data + settings. A detached cleanup process handles the userData deletion after Electron exits, sidestepping the LevelDB-locks-while-running problem that defeated manual cleanup attempts in the v0.7.17 debug. Confirmation dialog defaults to Cancel; "Yes, reset everything" is a deliberate click. Closes #341.
- **Ollama provider tile is always visible.** Previously: no Ollama daemon → no tile at all → users couldn't discover Fox supported local models. Now the tile shows state-aware hints — "Install Ollama from ollama.com/download" when no daemon, "Pull a model: ollama pull phi4-mini" when daemon is up but empty, and the standard model list once you have models pulled. Closes #337.

## Behind the scenes

- The `wizard-renders` redirect-fires + `test-hooks-safety` Playwright specs are both live and asserting in CI smoke for the first release in a row. The chicken-and-egg from v0.7.13's onboarding patch is fully unwound.
- This is the first release with a real (non-bypass) `qa/SMOKE_LOG.md` entry that the v0.7.15 gate was designed to require. The bypass streak ended at three.
