# v0.7.21 — Tooling cleanup

> **Heads up — clean install recommended.** Until Fox's upgrade path is fully validated end-to-end with automated smoke, the cleanest experience is to use **Tray → Reset Fox completely…** (v0.7.18+) or follow [`docs/RESET.md`](https://github.com/fox-in-the-box-ai/fox-in-the-box/blob/main/docs/RESET.md) before installing this release. This advisory will be removed once the upgrade path is verified across the matrix.

A no-user-facing-change release that closes the patch-system hygiene items the v0.7.15 audit kept queued. The kind of release that doesn't show up in chat but pays for itself the next time someone reaches for a maintainer tool.

## Highlights

- **`check-overlay-basis.sh` no longer destroys submodule work-in-progress.** The previous version did `git stash` + `git reset --hard` + `git clean -fdx` on every run; the stash was never popped, and the reset destroyed the working tree. On CI runners (always-fresh checkout) this was a no-op. For local dev runs where you had uncommitted changes in `forks/hermes-webui` or `forks/hermes-agent`, the script silently wiped them. v0.7.21 refuses to run if either submodule is dirty — clear error message, exit code 2, your work stays where you left it.
- **Orphan-patch detection.** v0.7.13 #331 root cause: `003-server-py-onboarding-redirect.patch` existed in `packages/fox-overlay/patches/webui/` from v0.7.13 onwards but wasn't added to the `series` file until v0.7.15 — for two releases the onboarding redirect shipped broken because the Dockerfile only iterates the series file, not the directory. `check-overlay-basis.sh` now catches that class at commit time: any `.patch` file in the directory that isn't in `series` fails the check with a clear "add to series or delete" message.
- **`regen-patch.sh` rewrite — actually works now.** The version shipped in v0.7.14 was broken-on-arrival per the v0.7.15 audit. It had two competing diff blocks; the second one copied the snapshot back over the developer's edits before computing the diff, so the output was always empty. The `# Wait that's not right. Let me redo:` comment shipped to main was the audit's smoking gun. The rewrite uses git itself as the diff engine: stack prior patches, commit baseline locally, drop into a dev shell, then `git diff HEAD` after the shell exits and reset to pristine. Trap-based cleanup so even an error mid-write leaves the submodule clean.
- **Playwright smoke suite: 18 → 24 specs.** A new `model-picker.spec.ts` folds in regression coverage for the Ollama tile and chat auto-preselect. Most of the new specs ship `describe.skip` for one release because they depend on either v0.7.21's just-added `/api/models` whitelist reaching `:stable` (one-release chicken-and-egg) or a `/test/seed-provider` test-mode hook that's queued for a future release. The skip targets are explicit in each spec's comment so future-you can unskip in the right release.

## Behind the scenes

- One small runtime change snuck into this otherwise-tooling-only release: `/api/models` added to the onboarding-redirect whitelist (`packages/fox-overlay/fox_overlay/webui_modules/onboarding.py`). Same shape as v0.7.17's `/test/` whitelist fix — the public read endpoint should work regardless of onboarding state, and the new model-picker smoke needs to hit it on fresh containers. Same one-release chicken-and-egg as v0.7.15 → v0.7.17 had with `/test/reset`.
- Jest count unchanged from v0.7.20 (83/83). No Electron source changes.
