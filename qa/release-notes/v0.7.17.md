# v0.7.17 — Anthropic, Gemini, and Bedrock providers actually work now

> **Heads up — clean install recommended.** Until Fox's upgrade path is fully validated end-to-end with automated smoke, the cleanest experience is to do a clean install: remove the existing container + image + data dir per [`docs/RESET.md`](https://github.com/fox-in-the-box-ai/fox-in-the-box/blob/main/docs/RESET.md) (or `packages/scripts/clean-windows-desktop.ps1` for Windows) before installing this release. This advisory will be removed once the upgrade path is verified across the matrix.

Three native providers were silently broken since the v0.6.0 fork-overlay migration — the container shipped without their Python packages, so adding a key and sending a message threw `ImportError: The 'anthropic' package is required` at first use. Fixed by installing the right `pyproject.toml` extras at build time. Same release also closes a latent onboarding-redirect bug that hid in `:stable` since v0.7.15.

## Highlights

- **Anthropic, Gemini (`google/gemini-*`), and Bedrock providers work out of the box.** Upstream hermes-agent's policy is to gate each provider's Python package behind an optional `pyproject.toml` extra (`[anthropic]`, `[google]`, `[bedrock]`). The container build was installing hermes-agent with no extras, so any user who picked one of these providers natively (not via OpenRouter) hit an ImportError at first message. Now all three are installed at build time. OpenRouter, OpenAI, Codex, and Ollama continued to work because their dependencies are in core.
- **Onboarding redirect no longer 302s the `/test/*` routes.** A latent bug in patch 003 (added v0.7.15, actually applied v0.7.16) was redirecting `/test/reset` to `/setup` on fresh containers. Production builds were never affected — `/test/*` routes are gated by `FITB_TEST_MODE=1` and don't exist in normal use — but CI smoke runs were hitting a broken assertion. Fixed by whitelisting `/test/` in `_SETUP_PREFIXES`.
- **`wizard-renders` redirect-fires Playwright assertions go live.** The spec was added in v0.7.13 and skipped in v0.7.15 because the patch-003 chicken-and-egg made it impossible to test against `:stable` at that PR's CI time. v0.7.16 advanced `:stable` with patch 003 applied; the spec can now actually validate that the redirect fires on a fresh install. It's the permanent regression net for #331 that the v0.7.13 retro called for.

## Behind the scenes

- Container size up about 50 MB (boto3 is the biggest contributor); build time up about 20 seconds.
- The latent `/test/*` bug had been live in `:stable` for two releases (v0.7.15, v0.7.16). It only surfaced in v0.7.17's PR CI because that was the first time PR-time `:stable` actually had patch 003 applied — exactly the kind of "passed CI because the bug wasn't testable yet" that the v0.7.13 retro warned about. Caught by the test the retro produced.
- The `test-hooks-safety` spec is now skipped for v0.7.17 only — same one-release chicken-and-egg as wizard-renders had. Unskip lands in v0.7.18.
