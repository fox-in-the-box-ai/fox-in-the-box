# v0.7.20 — Windows installs no longer fail on the first reboot

> **Heads up — clean install recommended.** Until Fox's upgrade path is fully validated end-to-end with automated smoke, the cleanest experience is to use **Tray → Reset Fox completely…** (v0.7.18+) or follow [`docs/RESET.md`](https://github.com/fox-in-the-box-ai/fox-in-the-box/blob/main/docs/RESET.md) before installing this release. This advisory will be removed once the upgrade path is verified across the matrix.

The release that closes the load-bearing Windows-install race [@bsgdigital](https://github.com/bsgdigital) caught: post-reboot Fox was checking for Docker before Docker Desktop had finished starting, bailing too early, and falling through to a recovery flow that wasn't needed. Plus three other items that surfaced in the same session.

## Highlights

- **Windows: Fox now waits patiently for Docker Desktop after install + reboot.** The post-reboot detection used to bail on the first `WSL_BACKEND_MISSING` diagnostic — a transient state during fresh Docker Desktop boot, because the WSL distros register a few seconds after the process starts. Fox now tolerates that signal as long as the Docker process itself is alive, with a streak counter so genuinely broken WSL still eventually escalates. Timeout extended from 3 to 4 minutes for slower hardware. Progress UI shows "Waiting for Docker WSL backend to register… (Ns)" so users see what's happening instead of a stalled spinner. Closes #361.
- **Ollama models now appear under "Ollama" in the picker, not "Custom".** Fixed at the active-model write — `provider: "ollama"` instead of `provider: "custom"`. Backend routing is unchanged (upstream aliases `ollama → custom` for the actual HTTP request, which is OpenAI-compatible either way). Only the picker categorization changes. Closes #278 (and the duplicate-display flavor of the same bug, #343, that was filed in v0.7.18 smoke).
- **Chat auto-selects a usable model on first open.** Previously you opened a fresh chat and the model picker was empty — you had to manually open it and pick something before you could send. Now a small overlay extension picks the first usable model on page load. If literally zero models are configured, the composer chip explicitly reads "Model not selected" with a hover hint pointing to Settings → Providers. Closes #344.
- **Wizard's "Could not enable local fallback" alert finally tells you what went wrong.** The backend used to swallow exceptions silently and the frontend defaulted to the unhelpful "unknown error". Now the backend collects exception context into an `errors` field and the frontend surfaces it (with a fall-through to HTTP-status + response body summary if even that's missing). The root-cause fix for the underlying Windows local-fallback failure is still pending [@bsgdigital](https://github.com/bsgdigital)'s `docker logs` from a fresh repro — but the next report will carry diagnostic content instead of a generic string. Partial close on #336.
