# v0.7.15 — The required smoke gate lands

This release closes the structural gap that let an onboarding regression ship silently for six versions. Playwright smoke is now a required check, every release must have a written audit-trail entry, and the patch-application pipeline finally mirrors what the Docker build actually does.

## Highlights

- **Playwright smoke is now a required CI check.** The "Phase 1 makes smoke required" line had been deferred indefinitely since v0.6.x. That deferral is exactly what let the onboarding-redirect break ship through six releases before a user filed it. The check is now wired; the branch-protection toggle is a one-time UI flip documented in `qa/playwright/README.md`.
- **Releases now require a written audit-trail entry.** The publish workflow refuses to ship a tag unless `qa/SMOKE_LOG.md` contains a matching `## vX.Y.Z` heading. Bypass entries are allowed for infrastructure-only releases as long as the reason is stated in the body.
- **The onboarding-redirect fix from v0.7.13 actually applies now.** The patch shipped two releases ago but was silently missing from the patch-series manifest, so the Docker build never applied it. v0.7.15 adds it to the series and ships a Playwright spec that asserts the redirect fires end-to-end.
- **Overlay basis check mirrors the Docker build.** The pre-build check that watches for upstream drift was applying each patch independently against a virgin submodule — which masked the missing-from-series bug entirely. It now stacks patches sequentially, the same way the Dockerfile does.
- **New `wizard-renders` regression spec.** Asset-served assertions run on every PR. The redirect-fires assertions ship with this release and become live in v0.7.16, once `:stable` advances and the chicken-and-egg unwinds.

## Behind the scenes

- The `qa/SMOKE_LOG.md` entry for v0.7.15 is itself a bypass entry — a release that adds a publish gate cannot pre-exist its own gate. v0.7.16 onward must carry real entries.
- A 6-perspective retro after v0.7.13 surfaced this as one of three load-bearing gaps in the release process. The other two — orphan-patch detection and a rewrite of `regen-patch.sh` — are queued for follow-up.

## What's next

- **v0.7.16: Windows installer UX.** Docker Desktop install-dialog z-order, access-mode modal layering, and the "installation auto-resumes after reboot" copy.
- A follow-up release closes the remaining meta-gaps: orphan-patch detection in the basis check, a working `regen-patch.sh`, and unskipping the redirect-fires assertions now that `:stable` is at the right version.
- v0.7.x continues until the bar is "I'd ship this to a stranger without warnings." v0.8.0 is gated on that.
